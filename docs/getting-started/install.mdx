import { Aside, Card, CardGrid, Steps } from '@astrojs/starlight/components';

Choose a release version first. The binary, container, crate, SDK, Homebrew
formula, and production docs should all identify the same release tag.

<CardGrid>
  <Card title="Homebrew" icon="seti:homebrew">
    `brew install leani-dev/tap/leani`
  </Card>
  <Card title="Release archive" icon="download">
    Download the archive and checksum for your platform from the matching
    `smart-byte/leani` GitHub release.
  </Card>
  <Card title="Container" icon="seti:docker">
    Pull the immutable `ghcr.io/smart-byte/leani:&lt;version&gt;` image produced by
    the same release workflow.
  </Card>
  <Card title="Cargo" icon="seti:rust">
    `cargo install leani --version &lt;version&gt; --locked`
  </Card>
</CardGrid>

<Steps>
1. Verify the release archive checksum or pin the container digest.
2. Run `leani --version` and record it with your deployment configuration.
3. Save the selected profile as `./leani.toml` and run `leani doctor --json`
   before allowing network or database access. Use `LEANI_CONFIG` or
   `--config` when the file intentionally lives elsewhere.
4. Continue with the deterministic [offline proof](/docs/getting-started/offline-proof/).
</Steps>

<Aside type="caution" title="Pre-release package names are prepared, not assumed">
  Before the first release exists, install commands can resolve only after the
  corresponding GitHub, crates.io, Homebrew, npm, and container artifacts have
  been published. Do not substitute an unpinned `main` build in a release
  rehearsal.
</Aside>
